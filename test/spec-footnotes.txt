# Footnote References

MD4X always recognizes footnote references written `[^label]` and footnote
definitions written `[^label]: content` at the start of a paragraph; the
extension is unconditional.

A footnote reference is a self-contained inline span that renders as a numbered
superscript linked to its definition. Definitions are emitted at the very end of
the document, in order of FIRST REFERENCE (not definition order), each wrapped in
a `footnote_def` block inside one `footnote_def_section`. A definition that is
never referenced is consumed and never emitted. The HTML renderer wraps the
section in `<section class="footnotes"><ol>`.

Ported from md4c `a8b0d3e` (#315), `54bfec0` (multi-line bodies) and `326fe25`
(refs swallowed by a link destination), plus the label-hashtable generalization `915676f` /
`19dd06f` those needed. MD4X has one dialect with every extension on, so the
examples below also show how footnotes compose with the other extensions;
md4c's "flag required" section cannot be expressed here, and its spoiler and
superscript interaction sections have no MD4X counterpart.


## Basic recognition

```````````````````````````````` example
Text with a footnote[^1].

[^1]: The footnote content.
.
<p>Text with a footnote<sup><a href="#fn-1" id="fnref-1-1">1</a></sup>.</p>
<section class="footnotes">
<ol>
<li id="fn-1">
The footnote content.<a href="#fnref-1-1" class="footnote-backref">&#8617;</a>
</li>
</ol>
</section>
````````````````````````````````

Word-style label:

```````````````````````````````` example
See note[^note].

[^note]: This is the note.
.
<p>See note<sup><a href="#fn-1" id="fnref-1-1">1</a></sup>.</p>
<section class="footnotes">
<ol>
<li id="fn-1">
This is the note.<a href="#fnref-1-1" class="footnote-backref">&#8617;</a>
</li>
</ol>
</section>
````````````````````````````````

Multiple footnotes in reference order:

```````````````````````````````` example
First[^a] and second[^b].

[^a]: Note A.
[^b]: Note B.
.
<p>First<sup><a href="#fn-1" id="fnref-1-1">1</a></sup> and second<sup><a href="#fn-2" id="fnref-2-1">2</a></sup>.</p>
<section class="footnotes">
<ol>
<li id="fn-1">
Note A.<a href="#fnref-1-1" class="footnote-backref">&#8617;</a>
</li>
<li id="fn-2">
Note B.<a href="#fnref-2-1" class="footnote-backref">&#8617;</a>
</li>
</ol>
</section>
````````````````````````````````

Definitions are emitted in reference order, not definition order:

```````````````````````````````` example
First ref[^b] then[^a].

[^a]: Note A.
[^b]: Note B.
.
<p>First ref<sup><a href="#fn-1" id="fnref-1-1">1</a></sup> then<sup><a href="#fn-2" id="fnref-2-1">2</a></sup>.</p>
<section class="footnotes">
<ol>
<li id="fn-1">
Note B.<a href="#fnref-1-1" class="footnote-backref">&#8617;</a>
</li>
<li id="fn-2">
Note A.<a href="#fnref-2-1" class="footnote-backref">&#8617;</a>
</li>
</ol>
</section>
````````````````````````````````


## Unreferenced definitions

A footnote definition that is never referenced in the document body is not
emitted in the output:

```````````````````````````````` example
No reference here.

[^1]: Unreferenced footnote.
.
<p>No reference here.</p>
````````````````````````````````


## Unknown label

A reference to an unknown label is left as literal text:

```````````````````````````````` example
Text with [^unknown].

[^1]: Only this one is defined.
.
<p>Text with [^unknown].</p>
````````````````````````````````


## Two references to the same label

When the same label is referenced more than once, both references receive the
same visible index number but unique backlink ids:

```````````````````````````````` example
First[^a] and again[^a].

[^a]: The note.
.
<p>First<sup><a href="#fn-1" id="fnref-1-1">1</a></sup> and again<sup><a href="#fn-1" id="fnref-1-2">1</a></sup>.</p>
<section class="footnotes">
<ol>
<li id="fn-1">
The note.<a href="#fnref-1-1" class="footnote-backref">&#8617;</a> <a href="#fnref-1-2" class="footnote-backref">&#8617;</a>
</li>
</ol>
</section>
````````````````````````````````


## Inline markup inside footnote content

Emphasis and other inline spans inside the footnote body are parsed normally:

```````````````````````````````` example
See note[^1].

[^1]: Footnote with **bold** and *italic*.
.
<p>See note<sup><a href="#fn-1" id="fnref-1-1">1</a></sup>.</p>
<section class="footnotes">
<ol>
<li id="fn-1">
Footnote with <strong>bold</strong> and <em>italic</em>.<a href="#fnref-1-1" class="footnote-backref">&#8617;</a>
</li>
</ol>
</section>
````````````````````````````````

## No definitions at all

When footnotes are enabled but the document contains no `[^label]:` definitions,
the `md_process_footnote_defs` function returns immediately without output:

```````````````````````````````` example
Just a paragraph.
.
<p>Just a paragraph.</p>
````````````````````````````````


## Mixed referenced and unreferenced definitions

Only referenced definitions are emitted; unreferenced ones are silently dropped:

```````````````````````````````` example
Only[^1] referenced.

[^1]: Used.
[^2]: Unused.
.
<p>Only<sup><a href="#fn-1" id="fnref-1-1">1</a></sup> referenced.</p>
<section class="footnotes">
<ol>
<li id="fn-1">
Used.<a href="#fnref-1-1" class="footnote-backref">&#8617;</a>
</li>
</ol>
</section>
````````````````````````````````


## Invalid definition syntax is not recognized

### Empty label (`[^]:`)

```````````````````````````````` example
[^]:
.
<p>[^]:</p>
````````````````````````````````

### Label with no closing bracket

If the label runs to end-of-line without a `]`, the line is not a definition:

```````````````````````````````` example
[^labelonly
.
<p>[^labelonly</p>
````````````````````````````````

### Closing bracket found but no colon

```````````````````````````````` example
[^1]! word
.
<p>[^1]! word</p>
````````````````````````````````

A continuation line indented with a tab is part of the footnote body:

```````````````````````````````` example
Text[^1].

[^1]: First line.
	Tab-indented continuation.
.
<p>Text<sup><a href="#fn-1" id="fnref-1-1">1</a></sup>.</p>
<section class="footnotes">
<ol>
<li id="fn-1">
First line.
Tab-indented continuation.<a href="#fnref-1-1" class="footnote-backref">&#8617;</a>
</li>
</ol>
</section>
````````````````````````````````


## Inline reference edge cases

### Unclosed bracket — no matching `]`

A `[^label` with no closing `]` is treated as literal text:

```````````````````````````````` example
Some [^label and more.
.
<p>Some [^label and more.</p>
````````````````````````````````

### Empty inline label `[^]`

An inline `[^]` (empty label between `^` and `]`) is treated as literal text:

```````````````````````````````` example
Text [^] here.
.
<p>Text [^] here.</p>
````````````````````````````````

## Fallthrough: invalid footnote definition falls through to link reference

A `[^` line that fails the footnote syntax check is retried as a regular link
reference definition.  Here `[^a b]:` has a space in the label so it is not a
valid footnote definition; it is consumed as a link reference with label `^a b`.
The valid `[^1]:` definition that follows is then correctly stored as a footnote:

```````````````````````````````` example
See[^1].

[^a b]: not-a-footnote
[^1]: A note.
.
<p>See<sup><a href="#fn-1" id="fnref-1-1">1</a></sup>.</p>
<section class="footnotes">
<ol>
<li id="fn-1">
A note.<a href="#fnref-1-1" class="footnote-backref">&#8617;</a>
</li>
</ol>
</section>
````````````````````````````````


## Label is not confused with regular link reference definition

A `[^label]: ...` line would also be a syntactically valid link reference
definition (label `^1`, destination `...`).  When footnotes are enabled, the
`[^` prefix is tried as a footnote first, so the line is consumed as a
footnote definition, not a link:

```````````````````````````````` example
Note[^1].

[^1]: content
.
<p>Note<sup><a href="#fn-1" id="fnref-1-1">1</a></sup>.</p>
<section class="footnotes">
<ol>
<li id="fn-1">
content<a href="#fnref-1-1" class="footnote-backref">&#8617;</a>
</li>
</ol>
</section>
````````````````````````````````


## Interaction with MD4X extensions

Footnote references win over the ATTRIBUTES extension: the span is
self-contained, with no content for a trailing `{...}` to attach to, so the
braces stay literal text:

```````````````````````````````` example
Attrs [^1]{.cls} here.

[^1]: body
.
<p>Attrs <sup><a href="#fn-1" id="fnref-1-1">1</a></sup>{.cls} here.</p>
<section class="footnotes">
<ol>
<li id="fn-1">
body<a href="#fnref-1-1" class="footnote-backref">&#8617;</a>
</li>
</ol>
</section>
````````````````````````````````

A reference swallowed by a link destination dies with it -- the `[^` opener is
disabled along with everything else the `(...)` ate, and its `]` closer (which
may sit outside the swallowed range) is killed with it rather than left to pair
with something else (md4c `326fe25`, which asserted here):

```````````````````````````````` example
[x]([^a) b]

[^a]: N.
.
<p><a href="%5B%5Ea">x</a> b]</p>
````````````````````````````````

Inside an alert:

```````````````````````````````` example
> [!NOTE]
> see[^1]

[^1]: n
.
<blockquote class="alert alert-note markdown-alert markdown-alert-note">
<p class="markdown-alert-title">Note</p>
<p>see<sup><a href="#fn-1" id="fnref-1-1">1</a></sup></p>
</blockquote>
<section class="footnotes">
<ol>
<li id="fn-1">
n<a href="#fnref-1-1" class="footnote-backref">&#8617;</a>
</li>
</ol>
</section>
````````````````````````````````

Inside an inline component:

```````````````````````````````` example
:badge[[^1]]

[^1]: n
.
<p><badge><sup><a href="#fn-1" id="fnref-1-1">1</a></sup></badge></p>
<section class="footnotes">
<ol>
<li id="fn-1">
n<a href="#fnref-1-1" class="footnote-backref">&#8617;</a>
</li>
</ol>
</section>
````````````````````````````````

Inside a table cell:

```````````````````````````````` example
| a[^1] |
|---|
| b |

[^1]: n
.
<table>
<thead>
<tr>
<th>a<sup><a href="#fn-1" id="fnref-1-2">1</a></sup></th>
</tr>
</thead>
<tbody>
<tr>
<td>b</td>
</tr>
</tbody>
</table>
<section class="footnotes">
<ol>
<li id="fn-1">
n<a href="#fnref-1-1" class="footnote-backref">&#8617;</a> <a href="#fnref-1-2" class="footnote-backref">&#8617;</a>
</li>
</ol>
</section>
````````````````````````````````

With highlight and emphasis in the same document:

```````````````````````````````` example
==hi== and _u_ and note[^1].

[^1]: ==body== _too_
.
<p><mark>hi</mark> and <em>u</em> and note<sup><a href="#fn-1" id="fnref-1-1">1</a></sup>.</p>
<section class="footnotes">
<ol>
<li id="fn-1">
<mark>body</mark> <em>too</em><a href="#fnref-1-1" class="footnote-backref">&#8617;</a>
</li>
</ol>
</section>
````````````````````````````````


## References inside other spans

A reference nested inside a link, emphasis or an image label still resolves;
one inside a code span does not (code spans are verbatim):

```````````````````````````````` example
[Link with [^1] inside](/u) and *em [^1] em* and `code [^1]` and ![img [^1]](/i).

[^1]: note
.
<p><a href="/u">Link with <sup><a href="#fn-1" id="fnref-1-1">1</a></sup> inside</a> and <em>em <sup><a href="#fn-1" id="fnref-1-2">1</a></sup> em</em> and <code>code [^1]</code> and <img src="/i" alt="img ">.</p>
<section class="footnotes">
<ol>
<li id="fn-1">
note<a href="#fnref-1-1" class="footnote-backref">&#8617;</a> <a href="#fnref-1-2" class="footnote-backref">&#8617;</a> <a href="#fnref-1-3" class="footnote-backref">&#8617;</a>
</li>
</ol>
</section>
````````````````````````````````

A reference inside a footnote body resolves too, and gets its own id:

```````````````````````````````` example
Outer[^o].

[^o]: contains [^i] nested.
[^i]: inner body.
.
<p>Outer<sup><a href="#fn-1" id="fnref-1-1">1</a></sup>.</p>
<section class="footnotes">
<ol>
<li id="fn-1">
contains <sup><a href="#fn-2" id="fnref-2-1">2</a></sup> nested.<a href="#fnref-1-1" class="footnote-backref">&#8617;</a>
</li>
<li id="fn-2">
inner body.<a href="#fnref-2-1" class="footnote-backref">&#8617;</a>
</li>
</ol>
</section>
````````````````````````````````

```````````````````````````````` example
<section class="footnotes">
<ol>
<li id="fn-1">

</li>
</ol>
</section>
````````````````````````````````

## Labels

A label may not contain whitespace, `[` or `]`; it is compared case-folded, so
`[^AB]` and `[^ab]` are the same footnote:

```````````````````````````````` example
Case[^AB] and [^ab].

[^ab]: folded
.
<p>Case<sup><a href="#fn-1" id="fnref-1-1">1</a></sup> and <sup><a href="#fn-1" id="fnref-1-2">1</a></sup>.</p>
<section class="footnotes">
<ol>
<li id="fn-1">
folded<a href="#fnref-1-1" class="footnote-backref">&#8617;</a> <a href="#fnref-1-2" class="footnote-backref">&#8617;</a>
</li>
</ol>
</section>
````````````````````````````````

Unusual but legal labels; `[^A b]` has whitespace so it is not a footnote
definition — it is an ordinary link reference definition with the label `^A b`,
and `[^A b]` with no footnote to match is an ordinary shortcut reference link to
it (md4c ae821cb; GitHub renders it the same way):

```````````````````````````````` example
Odd labels [^A b], [^ünï], [^*x*], [^1-2_3], [^], [^ ], [^a[b], [^a]b].

[^A b]: spaced
[^ünï]: unicode
[^*x*]: stars
[^1-2_3]: mixed
.
<p>Odd labels <a href="spaced">^A b</a>, <sup><a href="#fn-1" id="fnref-1-1">1</a></sup>, <sup><a href="#fn-2" id="fnref-2-1">2</a></sup>, <sup><a href="#fn-3" id="fnref-3-1">3</a></sup>, [^], [^ ], [^a[b], [^a]b].</p>
<section class="footnotes">
<ol>
<li id="fn-1">
unicode<a href="#fnref-1-1" class="footnote-backref">&#8617;</a>
</li>
<li id="fn-2">
stars<a href="#fnref-2-1" class="footnote-backref">&#8617;</a>
</li>
<li id="fn-3">
mixed<a href="#fnref-3-1" class="footnote-backref">&#8617;</a>
</li>
</ol>
</section>
````````````````````````````````


## A footnote-like bracket with no definition is an ordinary bracket

With no definition to match, `[^x]` is an ordinary bracket pair whose text
starts with the `^`, so it can still be an inline, full or collapsed reference
link, and the spans around it stay balanced (md4c `ae821cb`; GitHub renders all
four the same way — md4x has no superscript extension, so `^a^` stays text):

```````````````````````````````` example
[^x](https://example.test/path)
.
<p><a href="https://example.test/path">^x</a></p>
````````````````````````````````

```````````````````````````````` example
[^a^]()
.
<p><a href="">^a^</a></p>
````````````````````````````````

```````````````````````````````` example
[^x][ref]

[ref]: /u
.
<p><a href="/u">^x</a></p>
````````````````````````````````

```````````````````````````````` example
*a [^x](/u*) b*
.
<p><em>a <a href="/u*">^x</a> b</em></p>
````````````````````````````````

The md4x `[text]{attrs}` span applies the same way; a defined reference still
wins over the attributes:

```````````````````````````````` example
[^1]{.cls} and [^z]{.cls}

[^1]: n
.
<p><sup><a href="#fn-1" id="fnref-1-1">1</a></sup>{.cls} and <span class="cls">^z</span></p>
<section class="footnotes">
<ol>
<li id="fn-1">
n<a href="#fnref-1-1" class="footnote-backref">&#8617;</a>
</li>
</ol>
</section>
````````````````````````````````


## Reference labels are matched the way GitHub matches them

A reference label may carry surrounding whitespace and is not capped at 75
characters: GitHub resolves both, up to its 1000-byte label limit. md4c
`f5be4b7` rejects both; md4x takes only its O(n²) fix (a label holding a
bracket is rejected before the lookup hashes it):

```````````````````````````````` example
x[^ a] y[^a ]

[^a]: note
.
<p>x<sup><a href="#fn-1" id="fnref-1-1">1</a></sup> y<sup><a href="#fn-1" id="fnref-1-2">1</a></sup></p>
<section class="footnotes">
<ol>
<li id="fn-1">
note<a href="#fnref-1-1" class="footnote-backref">&#8617;</a> <a href="#fnref-1-2" class="footnote-backref">&#8617;</a>
</li>
</ol>
</section>
````````````````````````````````

```````````````````````````````` example
x[^aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa]

[^aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa]: note
.
<p>x<sup><a href="#fn-1" id="fnref-1-1">1</a></sup></p>
<section class="footnotes">
<ol>
<li id="fn-1">
note<a href="#fnref-1-1" class="footnote-backref">&#8617;</a>
</li>
````````````````````````````````
